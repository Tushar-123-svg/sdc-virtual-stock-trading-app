# Paper & Bell — Virtual Stock Trading App

**SDC Project Review — vanilla HTML, CSS & JavaScript only.**

## 1. Problem statement

New and aspiring investors rarely get to practice buying and selling
stocks before risking real money. Paper & Bell is a simulated trading
platform where a user can register an account, receive $100,000 in
virtual cash, buy and sell fictional stocks at simulated live prices,
track their portfolio's performance, compete against other registered
users on a returns leaderboard, read curated market news, and work
through short tutorials — all without any real financial risk.

## 2. Business system & modules

The platform has two distinct classes of user, each with its own
module:

- **User Module** — the trading experience: browsing the market,
  buying/selling, tracking a portfolio, maintaining a watchlist,
  viewing the competition leaderboard, reading news, and working
  through tutorials.
- **Admin Module** — platform operations: reviewing every registered
  trader's performance (and resetting/removing accounts), listing or
  delisting stocks and correcting their prices, and publishing market
  news that appears in the User module.

Every visitor starts at `login.html` / `signup.html`. After
authenticating, JavaScript reads the account's stored **role**
(`"user"` or `"admin"`) and redirects to the matching module — this
is the "module-wise redirection" the review asks for, and it also
protects each page: every module page calls `requireAuth()` on load
and bounces unauthenticated or wrong-role visitors back to the login
page.

## 3. Tech constraints honored

- **HTML, CSS, and JavaScript only** — no frameworks, no build step,
  no external libraries or CDNs. Fonts are system font stacks; charts
  are hand-built SVG generated by plain JS.
- **Layout** uses CSS Grid (page shell, dashboard stat grids, the
  centered auth screen) and Flexbox (nav bar, card rows, form rows).
- **Signup/Login** is implemented entirely with `localStorage` — see
  `js/storage.js` and `js/auth.js`. There is no backend or server.
- **Navigation between and within modules** is done in JavaScript:
  `js/user-nav.js` and `js/admin-nav.js` build each page's nav bar
  and attach `click` listeners that set `window.location.href`, and
  `login.html`/`signup.html`/`index.html` route by role in JS.

## 5. How to run it

No installation, no build step — it's static files.

**Easiest:** open `index.html` directly in a browser (double-click it).

**Recommended (avoids some browsers' local-file quirks):** serve the
folder with any static server, e.g.:

```bash
# Python (comes with most systems)
python3 -m http.server 8000
# then open http://localhost:8000
```

or, in VS Code, install the "Live Server" extension and click "Go Live".

## 7. Feature walkthrough for the review

**User Module**
- *Market* — every listed stock, live-simulated price ticking every
  3 seconds, search, star-to-watchlist, buy/sell via an order-ticket
  modal with validation (can't overspend or oversell).
- *Portfolio* — cash, holdings value, total value, total return, a
  hand-drawn SVG value-over-time chart, a holdings table with P/L,
  and a recent-orders log.
- *Watchlist* — starred stocks only.
- *Competition* — every registered trader ranked by live return,
  computed from real stored portfolios (not fake data).
- *News* — read-only feed of what the admin has published.
- *Learn* — five short, expandable investing lessons.

**Admin Module**
- *Overview* — trader count, stock count, news count, top performer.
- *Manage Users* — every trader's value/return, with Reset (back to
  $100,000) and Delete actions.
- *Manage Stocks* — add a new ticker, edit a price inline, delist a
  stock.
- *Manage News* — publish or remove headlines tied to a stock symbol.

## 8. Known limitations (by design, for a demo)

- All data lives in `localStorage`, so it's per-browser — it won't
  sync across devices, and clearing browser storage resets everything.
- Passwords are stored in plain text in `localStorage`. This is
  acceptable for a local teaching demo but would never be done in a
  real system (a real system would hash passwords server-side).
- Price movement is a random walk, not real market data.
